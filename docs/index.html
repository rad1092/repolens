READ-ONLY REPOSITORY TRIAGE

Fix the next repo problem.

RepoLens scans a local path or GitHub repository, shows what it could verify, and turns new maintenance regressions into a terminal or CI policy result.

Maintenance loop
  1. Configure and scan a repository
  2. Review evidence and scope
  3. Save the accepted baseline
  4. Fix an item and compare again

FOUR COMMANDS

Local once. CI every change.

01 / CONFIGURE

init

Create a documented policy and explicit path exclusions.

npm install --global \
  https://github.com/rad1092/repolens/releases/download/v0.2.0/rad1092-repolens-0.2.0.tgz

repolens init
02 / INSPECT

scan

Inspect the current repository or an owner/repository target.

repolens scan .
03 / ACCEPT

save

Keep the reviewed state as a versioned JSON baseline.

repolens scan . \
  --format json \
  --output .repolens/baselines/accepted.json \
  --fail-on none
04 / VERIFY

compare

Gate new findings without failing on accepted historical debt.

repolens compare . \
  --baseline .repolens/baselines/accepted.json \
  --fail-on new-warning

OUTPUT THAT TRAVELS

One model, four useful views.

  • Concise terminal triage for local work
  • Versioned JSON for baselines and automation
  • Standalone HTML for review or an artifact
  • GitHub Markdown summaries and annotations
Inspection scope

RepoLens reads tracked files and repository metadata while leaving the target unchanged. Permission gaps and rate limits stay visible as unknown. Dedicated security scanners remain the source for vulnerability findings.
